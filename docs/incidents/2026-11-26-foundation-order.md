# 事故复盘：地基未验收就起楼（2026-11-26）

> 级别：**A 级**（返工 8 个单元、40+ 次工具往返、约 2 小时）
> 影响面：u001–u008 全部重写；u009–u035 未改动，但长期处在"随时会被牵动"的风险里
> 结论：**流程事故，不是翻错字**。必须在流程上加硬约束，否则一定再犯。

---

## 1. 发生了什么

按顺序写内容时，我先把 u009–u035（27 课）全部写完，最后才回头修前 8 课的新词数不合规问题：

| 课 | 首现词（总） | 实词 | 问题 |
|---|---|---|---|
| u001 | 76 | 46 | 超出 20–25 三倍 |
| u002 | 39 | 28 | 超出 |
| u004 | 35 | 30 | 超出 |
| u008 | 16 | 16 | 不足 |
| 其余 | 22–25 | 19–23 | 合规 |

**这个矛盾从写第一批内容时就已经存在**，我当时判断"以后重写时一起修"，然后继续往后写了 27 课。结果：

1. **后面的课全部建立在"前 8 课词序"之上**。850 词覆盖是靠"每课新词 + 逐课累加"算出来的；把 u001 的一个词挪到 u003，u003 到 u035 每一课的"首次出现"计数都会跟着漂。
2. **重写被反过来绑住手脚**。为了不破坏 850/850 覆盖，前 8 课不能自由改写，只能"词序不动"地压文本——一篇 250 词的东西要绕着 76 个固定词重写。
3. **最后仍然要动词序**。实词口径一上，u001 46 个实词还是超；必须在 8 课**内部**腾挪 20 个词，等于 8 课全部再动一遍。

## 2. 根因（四条，按重要性排序）

1. **地基未验收就起楼。**
   前 8 课不是普通内容，是**词序地基**：`measure.js` 的覆盖账、练习解锁、调度器全部依赖它。
   地基没验收（新词数不合规），就不该往后写第 9 课。

2. **规则算不平，却没当场停下定口径。**
   76 个首现词 vs 25 个上限，算术上**不可能**合规。我当时用"基础课是例外"给自己解释，把口径问题（功能词算不算新词）拖成了内容问题——多花了整轮时间才明白：这不是写作问题，是**计数规则没定**。

3. **度量口径晚于内容确定。**
   "新词算不算 the / and / is" 是**全局约束**，必须在写第一个字之前定死。
   口径是集体约定的产物，事后才定，就等于让已经量产的内容集体不合规。

4. **缺少"改动影响面"工具。**
   在 `rewrite-check.js` 出现之前，改一个词是否会打乱后面 27 课，只能靠人脑推——而人脑推不准，所以只能靠"反复跑 measure 看数字变没变"来试错。

## 3. 已落地的纠正措施

| 措施 | 落地方式 |
|---|---|
| 改动前先查影响面 | `tools/rewrite-check.js <unitId> <draft.json>`：基准取 **git HEAD**（防止"替换一次把基准污染"），检查越界词 / 丢失本课新词 / 篇幅 |
| 单单元替换不再手改 JSON | `tools/replace-unit.js <unitId> <draft.json>`：大括号配对定位，自动重算 `words` 数组 |
| 口径写进 SPEC 并三处同步 | §4.4.1：功能词不计、区间 20–30、`measure.js` / `checks.js` / `test-checks.js` 必须一致 |
| 事故记录进仓库 | 本文件 + SPEC 附录条目 + HANDOFF 顶部提示 |

## 4. 硬约束（可判定，下次照这个查）

1. **顺序约束**：单元 `i+1` 开工前，单元 `1..i` 的 `measure.js` 必须**全绿**。有一条红的，不许往后写。
2. **口径先行**：任何影响全局计数的规则（新词、超纲、长度区间），必须先写进 SPEC、三处脚本对齐，才允许量产内容。
3. **改动必查影响面**：动到已存在单元的任何词，落盘前必须跑 `rewrite-check.js`。
4. **不许"先记 TODO 后补"跨越 3 个以上单元**：待修项一旦积压到第 3 课，停止写新内容，先清账。
5. **算术先验**：任何"每单元 N 个"的规则，先做除法验算（总词数 ÷ 单元数 ≤ 上限？），再开工。算不平就先改规则，不要指望内容去凑。
